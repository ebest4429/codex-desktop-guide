## Phase 4 목표

검색 기능 연결, 모바일 반응형 보완, 전체 QA 후 최종 배포 완성.
Phase 3까지 완성된 콘텐츠를 기반으로 품질을 높이는 단계.

---

## 전제 조건 (Phase 3 완료 사항)

- 29개 페이지 콘텐츠 전부 완성
- 공통 컴포넌트 실제 콘텐츠에서 동작 확인
- GitHub Pages 배포 URL 정상 운영 중

---

## 구현 항목 및 순서

### 1. 검색 기능 구현

> 취지: Phase 2에서 헤더 검색바 자리만 잡아뒀음. Phase 4에서 실제 기능 연결.
> 정적 사이트이므로 클라이언트 사이드 검색(pagefind 또는 fuse.js)으로 구현.

- 검색 라이브러리 선택 및 협의 (pagefind / fuse.js / 직접 구현)
- 콘텐츠 인덱싱 (빌드 시 자동 생성)
- 검색바 기능 연결 (실시간 결과 표시)
- 검색 결과 페이지 또는 드롭다운 구현

### 2. 모바일 반응형 보완

> 취지: Phase 2, 3는 데스크톱 우선. Phase 4에서 모바일 뷰 보완.

- 사이드바: 모바일에서 숨김 + 햄버거 메뉴 토글
- 레이아웃: 모바일 1단 구조
- 카드/아코디언: 모바일 너비 최적화
- 헤더: 모바일 높이 조정

### 3. 전체 QA

- 29개 페이지 전수 확인 (콘텐츠 누락, 링크 오류, 레이아웃 깨짐)
- 사이드바 필터링 — 모든 항목 정상 동작 확인
- 배포 URL에서 전체 페이지 확인
- 검색 기능 동작 확인

### 4. 성능 최적화 (선택)

- 이미지 최적화 (스크린샷 사용 시)
- 폰트 로딩 최적화
- 빌드 산출물 크기 확인

### 5. 최종 배포 확인

- GitHub Actions 워크플로 정상 실행 확인
- 배포 URL 전체 기능 최종 검증
- 커스텀 도메인 설정 (필요 시 — 사용자 결정)
