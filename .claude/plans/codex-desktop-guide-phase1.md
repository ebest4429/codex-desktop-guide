# Phase 1 — 기술스택 협의 + 전체 구조 설계

> 참조: `.claude/plans/codex-desktop-guide-master.md`
> **이 Phase의 목표:** 기술스택 결정 + 전체 페이지·콘텐츠·디자인 구조 확정.
> 구현은 하지 않는다. 구조가 확정되지 않은 상태에서 구현 진입 시 방향 수정이 반복된다.

---

## 작업 항목

### 1. 기술스택 협의 및 결정

> 취지: 프로젝트 구상의 기술스택 항목이 "추천"으로 남아 있다.
> 가이드 웹사이트 특성(문서형, 검색, 사이드바, 다크테마 등)에 맞는 스택을 협의해야
> 이후 구조 설계와 구현이 일관성 있게 진행될 수 있다.

- ✅ 후보 기술스택 제안 및 비교 (빌드도구, 문서 프레임워크, CSS 방식)
- ✅ 배포 환경 결정 → Vercel
- ✅ 기술스택 최종 확정 및 마스터플랜 기록 → Next.js + Tailwind CSS

### 2. 전체 페이지 구조 설계

> 취지: 사이드바 네비게이션 구조와 페이지 계층이 확정되어야
> 콘텐츠 작성 순서와 컴포넌트 설계를 진행할 수 있다.

- ✅ 최상위 메뉴 구성 확정 (개요 / 사용법 / 주요기능 / 메뉴소개 + 구분선 + 모델/컨텍스트/구독/스킬/스레드/MCP)
- ✅ 하위 페이지 구성 확정 (최대 1단계. 기능 1개=페이지 1개. 구분선 이하=단일 페이지+아코디언)
- ✅ URL 구조 결정 (/overview, /usage/[slug], /features/[slug], /menu/[slug], /model 등 단순 구조)

### 3. 콘텐츠 구조 설계

> 취지: "기타" 항목(모델, 컨텍스트, 구독, 스킬, 스레드, MCP, 설정 페이지 등)의
> 범위와 깊이가 미정이다. 콘텐츠 범위를 먼저 확정해야 페이지 수와 작업량을 가늠할 수 있다.

- ✅ 각 섹션별 콘텐츠 항목 목록 작성 (실제 화면 기반 확정)
- ✅ 콘텐츠 작성 우선순위 결정 (1순위: 개요·사용법·구독 / 2순위: 스킬·MCP·자동화·작업트리 / 3순위: 설정 전체 / 4순위: 모델·컨텍스트·스레드·환경)

### 4. 디자인 시스템 정의

> 취지: 다크테마·Pretendard·카드형/아코디언 방향은 확정됐으나
> 색상 팔레트, 컴포넌트 스펙, 간격 기준 등 세부 디자인 시스템이 미정이다.
> 구현 전 기준이 있어야 일관성 있는 UI 개발이 가능하다.

- ✅ 색상 팔레트 정의 (배경 #0d0d0d계열, 텍스트 #f5f5f5 흰색 계열, 강조 #10a37f, 경계선 #2a2a2a)
- ✅ 타이포그래피 스케일 정의 (타이틀 28px/700 ~ 보조 13px/400, 본문 15px)
- ✅ 공통 컴포넌트 목록 확정 (사이드바, 검색바, 카드, 아코디언, 구분선, 코드블록, 배지, 브레드크럼)
